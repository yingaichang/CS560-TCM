# 期末部署元件

## Ubuntu 主機

Ubuntu 已透過 Docker Compose 部署網站。部署服務在首頁 HTTP 200 後保存不含內容的版本與時間證據，管理員狀態頁會比對執行版本並實際檢查 Caddy 至應用程式的回應。
正式網址的資源版本另行比對；Ubuntu 健康不代表學校上游轉送已切換。不得把主機帳密或存取憑證加入儀表板。

## 資料庫伺服器

Ubuntu 使用 Compose 內部的 PostgreSQL；本機開發保留 SQLite。正式建置產生相容的 PostgreSQL schema，已審查並套用增量結構更新。
管理員狀態頁實際執行唯讀連線查詢及必要資料表／欄位比對。API 連線與欄位比對成功不代表所有臨床、報名或個人服務功能已完成。
驗證僅保存成功／失敗、時間及測試範圍，不保存連線字串、查詢結果或業務資料。

## 自動盤點與資料邊界

開發模式在原始碼變更後重新掃描；正式建置前更新快照。管理員頁面每三十秒重新載入最新部署快照。
自動掃描限於 src 的程式碼與既有證據參照，不讀取環境檔案、憑證目錄、資料庫或日誌。
快照只包含來源路徑、行號、請求方法、狀態及掃描時間。新增本機服務路由與呼叫會自動列入盤點。
原始碼接線證據與實際服務連通測試分開顯示；不得因新增設定或模型而自動宣稱主機或遠端資料庫已連接。

## 後續每週作業維護

執行 `npm run dev` 會啟動來源監看；執行 `npm run build` 前會自動更新盤點。
也可用 `npm run architecture:update` 立即掃描；部署後頁面每三十秒讀取目前部署版本的快照及唯讀健康檢查，不會讀取開發電腦或替尚未部署的變更宣稱成功。
新增固定本機網址的 fetch 呼叫與對應匯出請求方法，會自動出現在安全盤點。動態網址與外部服務保留未知，需補上經審核的架構定義與驗證。
主要業務架構在 src/lib/architectureMap.ts 的 componentDefinitions、connectionDefinitions 與 architectureWorkflows 維護；每個已連接項目必須有可核對的來源依據。
執行 `node scripts/test-architecture-status.cjs --record` 可記錄受保護架構頁的隔離測試時間；它不會把 Ubuntu 或遠端資料庫標為已連接。
使用 `node scripts/test-architecture-discovery.cjs` 驗證自動發現、來源失效與敏感資料排除。
實際部署測試只提交不含服務回應本文的結果、時間與範圍，經確認後再變更規劃狀態；不可匯入原始回應、連線字串或日誌。
